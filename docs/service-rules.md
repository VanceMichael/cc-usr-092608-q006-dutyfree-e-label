# 监管服务规则

电子标签监管服务在领域资料之上落地可执行规则，全部状态变化以追加事件
（`src/event_store.py`）持久化，服务重启时回放恢复。

## 关系模型

```
商品型号 ── 进口批次 ── 实物件(序列号，终身不变)
   │            │           ├── 仓位（入区/分装/换仓）
   │            │           ├── 实物状态（在区/已出区/退运/销毁）
   │            │           └── 二维码载体（可因破损补发而替换）
   │            └── 通关单证（入区锁定，核放比对）
   └── 资料：成分声明 / 原产地证明 / 中文说明 / 通关单证
             └── 标签草案 → 资料审核 → 签发 → 不可变正式版本
```

## 关键规则

1. **两职分离**：资料审核岗确认资料、审核草案；标签签发岗只能引用“已确认”
   资料签发，且审核人与签发人不得为同一人员。
2. **版本不可变、二维码单指向**：正式版本一经签发不可修改；内容变更必须走
   新资料→新草案→新版本。每个码在任一时刻只指向一个正式版本。
3. **消费者公开视图白名单**：扫码仅返回中文名称、成分、原产地、中文说明、
   通关摘要与版本号；企业配方附件（`confidential_attachment`）不进入公开视图。
4. **件数守恒**：分装、换仓、部分放行、退运、销毁逐件移动，身份与数量一起
   变化，任何移动都不产生或吞没实物。
5. **破损补发**：新码接续同一序列号的全部历史，旧载体立即置“已停用”，旧码
   不能再入区、不能核放，消费者扫旧码只看到停用提示。
6. **冻结隔离**：抽检异常或成分更正只冻结关联批次（挂旧版本的在区批次），
   冻结批次禁止移动与核放，其他商品、其他批次不受牵连。
7. **海关核放**：
   - 申报时锁定每件实物码实际指向的标签版本；
   - 核放时若实物已不在区、批次被冻结、版本偏离锁定值或通关单证与入区单证
     矛盾，核放单停在“人工处理”，库存不动；
   - 同一核验结果编号重复提交是幂等的，返回原单且不再次扣减库存。
8. **召回**：按批次或商品型号圈定已出区实物，逐件记录销售状态（待售/已售）
   与通知进度；消费者扫码叠加召回提示。
9. **重启恢复**：`pending_recovery()` 列出未完成出区核放（待核放/人工处理）
   与待召回通知，供应用启动后优先处理。
10. **按序列监管查询**：`serial_query()` 同时给出审批依据（审核人、签发人、
    四份确认资料、内容指纹）、码值替换链、逐笔库存去向，以及每个历史时点
    消费者扫码能够读取的中文信息。
